# 実装状態・議論状態の視覚言語（design / discussion / code mode 用）

実装途上の手法や議論の結論を描くときは，構成要素の **状態** を一目で区別できるようにする．
両スタイル（sketchnote / paper-figure）で同じ意味の記号を使い，**図の隅に小さな凡例を必ず入れる**．

| 状態 | 意味 | sketchnote での表現 | paper-figure での表現 |
|------|------|--------------------|----------------------|
| ✅ implemented | 実装済み・合意済み | 実線の手描き枠＋薄い塗り | 実線の角丸矩形＋淡い塗り |
| 🟡 partial | 部分実装・スタブ | 実線枠を半分だけ塗る＋「WIP」の小さな付箋 | 枠の右上に小さな「WIP」タグ，塗りは斜線ハッチ |
| ⬜ planned | 計画のみ（未実装） | 鉛筆風の破線枠，中は白 | 破線枠，塗りなし，ラベルはグレー |
| ❓ open | 未決定・複数案 | 「？」の付いた黄色い付箋を貼る，分岐矢印を2本 | 小さな菱形ノード＋「?」，候補を細い分岐線で |
| ✕ rejected | 却下した案 | 端に小さく描いて赤ペンで ✕，薄く | 図の外側の小パネルにグレーで，取り消し線 |
| ⚠ discrepancy | 論文/メモとコードの食い違い | 赤い「！」の吹き出し | 小さな警告三角＋短い注記 |

## ルール

- 状態の記号は **主役の機構図を邪魔しない大きさ** にする（主体図解 75–85% の原則は維持）．
- 図の本体は「現在の合意・実装に基づく構成」．却下案は本体に混ぜず，端の小パネルにまとめる．
- 未決（❓）は具体的な選択肢名を書く（例：「τ: linear? / cosine?」）．「未定」だけにしない．
- code / design mode ではモジュール名の下に短いコード上の名前を添えてよい（例：`RouterBlock`，`router.py`）．**コードそのもの（複数行のコード片）は描かない．**
- 凡例は 1 行で：`✅ done  🟡 WIP  ⬜ planned  ❓ open` 程度の短さ．言語はユーザーが選んだ図の言語に合わせる．
- 版番号と日付（例：`design v3 · 2026-10-28`）を右下の小さな文字で入れる（sketchnote ではページ番号の近くに手書き風で）．
